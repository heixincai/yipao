# 宜跑 v0.1

微信原生小程序 + 微信云开发的“约跑”MVP 骨架。产品背景、范围与决策见 `CONTEXT.md`、`docs/scope-v0.1.md` 与 `docs/adr/`。

## 结构

```text
miniprogram/            小程序前端
  pages/index/          发现（我的跑点 / 全杭州 / 单次定位）
  pages/publish/        发布约跑帖
  pages/post/           帖子详情（加入/退出/取消/确认到场/帖内动态）
  pages/profile/        我的资料与参与记录
  pages/profile-edit/   完善昵称、头像、常跑点等
cloudfunctions/         云函数（登录、跑者、跑点、帖子、帖子动作）
docs/                   产品文档、ADR、backlog
```

## 本地运行步骤

1. 安装微信开发者工具，用你的微信扫码登录。
2. 导入本目录：工具里选择「导入项目」，项目目录选 `yipao`。
3. 把 [project.config.json](./project.config.json) 中的 `appid` 换成你的小程序 AppID（个人主体即可开始）。
4. 在微信公众平台开通云开发环境，记下环境 ID；填入 [miniprogram/config.js](./miniprogram/config.js) 的 `envId`（只有一个环境时可留空）。
5. 在云开发控制台创建四个集合：`runners`、`runSpots`、`spotRequests`、`posts`。权限先都设为「仅创建者可读写」——本骨架所有读写都走云函数，客户端不直连数据库。
6. 在开发者工具中对 `cloudfunctions/` 下每个函数目录右键 →「创建并部署：云端安装依赖」。
7. 编译运行。第一次进入会自动创建跑者记录；首次打开发现页会自动种入杭州示例跑点。

> 示例跑点只是占位数据，上线前需要人工核对名称、地址和坐标，再通过管理后台确认。

提审上线前还需要补齐：小程序备案、用户隐私保护指引（位置、头像昵称、订阅消息用途都要声明）、wx.getLocation 接口申请与类目配置。这些属于账号侧工作，详见 ADR-0006。

## 还没接线的部分

- **订阅消息推送**：客户端已在“加入/发布”等动作请求授权，云函数里保留 `notify()` 接入点（当前只打日志）。需要在公众平台申请模板，把模板 ID 填入 `config.js`，再在 `postAction/index.js` 与 `post/index.js` 的 `notify` 里真正调用 `cloud.openapi.subscribeMessage.send`。
- **GPS**：`pages/index/index.js` 的“找离我近的”会调用 `wx.getLocation`。需要按 ADR-0004/0006 先在小程序后台申请接口权限；未开通或用户拒绝时，自动退回跑点模式，核心功能不受影响。
- **管理员后台**：跑点审核、举报处理目前没有页面，先直接在云开发控制台维护 `spotRequests` 与相关集合。

## 规则速查（与文档一致）

- 浏览不需要资料；发帖/加入前必须完成昵称 + 至少一个常跑点。
- 帖子只挂在受管跑点；时间与跑点发布后不可改，改期须取消重发。
- 2–5 人小组，先到先得直接加入；开跑前 2 小时可自由退出，之后退出或未到场记一次爽约。
- 发起人取消帖子时参与者无过错；跑后由发起人确认到场名单。
- 不做后台/持续定位、不做私聊、不做押金评分、不收集手机号。
